# Учёт дилеров 8.9.64 — подготовленные исправления

Дата: 2026-09-21.
База: опубликованный Windows 8.9.63, ветка turso-sync-8963-from-8962.
Рабочая ветка: fix-8964.

## Реализовано
- Карточка дилера: одна строка на накладную, отдельные строки оплат и начального долга; пять колонок. Двойной щелчок открывает только выбранный чек, закрытие возвращает к списку.
- Старые renderer-patch.js и pdf-compact-8938.js не заменяют современный обработчик JPEG WhatsApp после его установки. Сохраняется сумма вместе со знаком ₽.
- Первое подключение к назначенному главному компьютеру блокируется, если локальные операции отсутствуют или отличаются на сервере. Локальные данные не заменяются, прежняя резервная копия не перезаписывается. Повторная проверка после ожидания сохранения резерва защищает оплату, введённую во время ожидания.

## Проверка и ограничения
- Все локальные prebuild:win тесты прошли, включая три новых сценария сохранности оплат.
- В Windows smoke добавлены проверки окончательного обработчика WhatsApp, положения ₽ на одной строке, списка документов, двойного щелчка и возврата к списку.
- Windows сборка и эти UI smoke ещё НЕ запускались: git push заблокирован автоматической проверкой разрешений. Нужно явное разрешение пользователя отправить исходные исправления в его репозиторий saypudsoffitto-a11y/uchet-dilerov-updates и продолжить выпуск.
- 8.9.64 НЕ опубликована, манифест обновления НЕ переключён.
- Причина конкретной пропажи оплат пользователя НЕ подтверждена. Для сравнения с резервом 20 сентября нужен текущий резерв с пострадавшего компьютера. Автоматическое восстановление старого резерва не выполнялось.
- macOS не собиралась и не публиковалась в этой работе.

## Продолжение
1. После разрешения отправить fix-8964 в origin; workflow build-8964-candidate.yml собирает Windows и выполняет существующие и новые проверки.
2. Устранить любые реальные ошибки UI проверок до публикации.
3. Публиковать только проверенные байты, сверить SHA256 и переключить latest.json. Старый publish-8963-verified.yml нельзя запускать для нового релиза: он привязан к 8.9.63.
4. Отдельно сверить пользовательские оплаты, не заявлять о восстановлении без проверки его базы.
