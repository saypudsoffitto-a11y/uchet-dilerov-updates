# СОФФИТТО — мобильный учёт, первый рабочий этап

27 сентября 2026. База исходников: commit 23b5490. Ветка feature/mobile-dealers-v1.

## Реализовано

- Мобильный веб-интерфейс `/mobile/`, адаптированный для iPhone и Android.
- Поиск дилера, просмотр долга/аванса, список последних 100 оплат.
- Внесение наличной оплаты или перевода с подтверждением дилера и суммы.
- Создание дилера с обязательным телефоном, нормализация 8/+7 и проверка дублей.
- Новые записи сохраняются в существующих `state.dealers` / `state.ops`, читаются настольным приложением после синхронизации.
- Денежные суммы передаются целым числом копеек. Сервер вычисляет баланс при записи.
- Идемпотентность: тот же requestId возвращает прежний результат даже после удаления оплаты на компьютере. Другой запрос с тем же ID отклоняется.
- Незавершённый запрос сохраняется на устройстве до отправки. При потере подтверждения новые операции заблокированы до проверки. Приложение не сообщает об успехе до ответа сервера.
- Отдельный мобильный ключ, хранящийся только в памяти страницы; мобильный API не отдаёт настройки синхронизации или полный state.
- CAS-хранилище; последовательная запись файлового backend в одном процессе.
- Защита от незаметного удаления мобильной карточки при отправке старого каталога с ПК.

## Локальный запуск

Node.js 20+. Для файлового backend дополнительные пакеты не нужны.

```bash
cd server
SYNC_TOKEN=local-desktop-key MOBILE_TOKEN=local-mobile-key DATA_DIR=/tmp/soffito-mobile-test node server.js
```

Открыть `http://localhost:8787/mobile/`. На реальном телефоне требуется HTTPS.
Тестовые ключи выше — только для локальной проверки. Для рабочего сервера нужны разные случайные ключи.
Сначала общая база должна быть подключена через существующий desktop protocol 2 (выбран главный компьютер); новая пустая база не подменяет рабочую.

```bash
node --test mobile.test.cjs store.test.cjs server.integration.test.cjs
```

Для первого подключения использовать сервер с постоянным DATA_DIR либо существующий Turso. Нельзя запускать несколько процессов с одним файловым DATA_DIR — для нескольких экземпляров использовать CAS в Turso.

## Что ещё не завершено

- На рабочий сервер изменения не развёрнуты; ввод оплат с реального телефона не проверен.
- Полная миграция компьютеров к равноправным точечным изменениям каталога ещё не сделана. Пока старый протокол «главный/рабочий» сохранён; при конфликте каталога требуется загрузить свежие данные на ПК.
- Нет IPA/App Store/TestFlight-сборки. Это первый мобильный веб-клиент с manifest для добавления на главный экран, без офлайн-кэша.
- Нет персональных аккаунтов/ролей, выдачи и отзыва ключей по устройствам, ограничения попыток входа. До публичного запуска нужен отдельный этап авторизации и согласования доступа.
- История запросов на сервере сохраняется без очистки для надёжного предотвращения повторов; архивирование требует отдельного правила хранения.
- Черновик незавершённой операции хранится в localStorage. Очистка данных браузера удалит его. При неизвестном результате после очистки сначала проверить историю оплат на сервере.
- Нужна проверка синхронизации с фактически установленной Windows/macOS-сборкой и настройками сервера. Манифест 8.9.76 найден, но это не доказывает установленную версию на всех ПК.
