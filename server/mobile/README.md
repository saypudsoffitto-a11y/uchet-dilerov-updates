# Мобильный кабинет — первая реализация

Ветка разработки от fix/payment-dealer-selection (8.9.76), ещё не опубликована. Маршрут после развёртывания: /mobile/ на существующем сервере. Данные записываются через master-protocol в общую базу компьютеров.

Реализованы вход владельца, поиск и создание дилеров, оплата, долг, история, поступления за день по Москве, очередь повторной отправки, оболочка PWA. Защита от дублей хранит идентификаторы запросов на сервере. Числовые ID совместимы с настольным интерфейсом.

## Настройка перед выпуском

MOBILE_PASSWORD — отдельный секретный пароль владельца длиной от 16 символов, не SYNC_TOKEN. MOBILE_ORIGIN — точный HTTPS origin сервера без завершающего слеша. Секреты задаются средствами хостинга. Использовать существующую Turso базу. Без настройки API закрыт. Cookie HttpOnly, Secure, SameSite=Strict, 12 часов, сбрасывается после перезапуска сервера. POST проверяет Origin и Content-Type. Лимит входа — 10 попыток в минуту на процесс.

Проверки: npm test в server; затем на тестовом сервере проверить iPhone/Safari, вход, оплату, появление её на трёх ПК, конфликт ревизии, потерю ответа и повторную отправку. Только после этого рабочий выпуск.

## Текущие ограничения

Это исходники первой версии, не готовая ссылка для рабочего приёма денег. Нет проверки на реальном iPhone, настройки мобильного доступа и рабочего развёртывания. Один пользователь — владелец. App Store не используется.

Очередь хранится на телефоне в localStorage; очистка данных браузера удаляет неподтверждённые записи. Работа без связи возможна в уже открытом кабинете. После перезапуска без интернета список дилеров пока не восстанавливается: API не кешируется. Ошибка первой записи блокирует очередь — интерфейс исправления/отмены требует реализации перед рабочим выпуском. Историю после обновления надо открыть заново.
